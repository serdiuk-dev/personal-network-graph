## Текущее состояние

Команды выполняются на VDS от root:

    systemctl list-timers pnet-backup.timer pnet-monitor.timer --no-pager
    cat /opt/pnet-backups/.automation/monitor-status.json
    systemctl show pnet-backup.service pnet-monitor.service -p Id -p Result
    df -h /opt/pnet-backups

Проверять время checkedAt: старый отчёт не подтверждает текущее состояние.
Монитор работает каждые пять минут и сообщает локально о проблемах
backup и контейнеров. Контроль свободного места выполняется отдельно.

## Действия при ошибке

- Посмотреть журнал нужного сервиса и время последнего успешного backup.
- Не удалять recovery.json и deploy-recovery.json вручную.
- Восстановление API после backup: private-backup.md.
- Восстановление после deployment: reliable-deploy.md.
- Не запускать параллельные изменения в обход общего lock.
- Повторный backup запускать после устранения причины ошибки:
  он временно останавливает API для согласованного снимка.

## Документы компонентов

- private-backup.md — backup PostgreSQL и contact media, восстановление API.
- reliable-deploy.md — healthchecks, deployment и rollback.
- container-logging.md — ротация логов контейнеров.
- local-monitor.md — локальные проверки и отчёты.
- backup-retention.md — политика хранения.
- retention-preview.md — предварительный расчёт без удаления.

## Хранение и ограничения

Backup выполняется ежедневно в 04:15 Europe/Kyiv.
Автоматическое удаление выключено. Preview сохраняет все успешные наборы
за последние 30 суток и минимум 14 последних, а также защищённые наборы.
Существующие ручные, неполные и неизвестные наборы сохраняются.

Контакты, фотографии, секреты, backup и оперативные отчёты остаются
на VDS вне Git. Внешнее хранилище не согласовано.
Локальный backup не защищает от потери VDS или его диска.

Health endpoint проверяет работу приложения, а не готовность БД.
Статус unhealthy сам по себе не запускает автоматический restart.
Внешние оповещения и обнаружение недоступности всего VDS не реализованы.
Перезагрузка VDS и принудительный production rollback не проводились.
Новые backup-наборы не объявляются проверенными восстановлением:
ранее подтверждённая проверка восстановления относится к своему набору.
