# v0.40.0 — Navigation / Accessibility / UI consistency

Status: validated for stable release.
Date: 2026-09-28
Baseline: v0.39.0 / 665cfd6a60fc4939a1710db113f835f1cd183557

## Audit findings
- Active navigation buttons were disabled instead of exposing current-page state.
- Several form controls relied on placeholders; Graph Styles had two controls
  inside one Color label.
- People and Relationships Edit scrolled the window instead of the app container.
- Nested People panels lacked focus transfer and restoration.
- Table scrolling was not explicitly keyboard reachable.
- Most existing error messages had no alert semantics.
- Graph and Edge Styles reset persisted changes without confirmation.

## Minimal scope
- One named main landmark, skip link, current-page state and per-view document title.
- Focus the content on navigation and the existing form on Edit in People,
  Relationships and Contact Channels.
- Named, focusable People panels with focus restoration on close.
- Persistent visible labels for previously unlabelled form fields and distinct,
  contextual accessible names for Graph Styles controls.
- Named keyboard-focusable regions for the three horizontally scrolling tables.
- Alert semantics for existing errors and status semantics for loading/save messages.
- Confirm before persisting Graph/Edge Styles resets.
- Upcoming/History pressed state and focus restoration after view loading.
  Reminder endpoints, filtering, scheduling and auto-refresh interval are unchanged.

## Validation before VPS build
- Source-only audit covers the 21 supplied files at the stable baseline.
- TypeScript syntax and strict type checks passed in an isolated local harness.
- DOM tests passed with React 19.2, jsdom and mocked API responses: main navigation,
  single main landmark, labels, edit focus, opening/closing all three People panels,
  table regions, reset cancellation/confirmation and Upcoming/History focus.
- All 42 existing fetch call expressions are unchanged.
- Local harness dependencies are not project dependencies and are not in the patch.
- Docker Node 24 with the repository lockfile remains the authoritative build gate.

## Browser acceptance after deployment
- Tab reveals Skip to content; Enter moves focus to the current view.
- Tab/Shift+Tab and Enter/Space operate navigation with visible focus.
- Edit focuses and reveals the correct form; opening a People panel focuses it;
  closing it returns visible focus to its opening button.
- Labels remain visible with populated fields; table regions scroll by keyboard.
- Cancel each style reset: no saved values change and no PATCH is sent.
- Upcoming/History retains focus after loading; Open person reveals Events / Reminders.
- Check Graph and all forms at 360 / 768 / 1440 px for responsive regressions.

## Boundaries
This is an accessibility baseline, not a complete WCAG conformance claim.
Sigma canvas keyboard traversal and screen-reader graph equivalence are not
implemented by this patch; Graph search and filters retain their existing behavior.
No API, database, migrations, dependency, adapter or scheduler changes.
Prisma remains 6.19.3; Docker Node 24 remains authoritative.
Reminder feature phase is complete. Social adapters and final cleanup stay deferred.
