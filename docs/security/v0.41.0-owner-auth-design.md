# v0.41.0 — Owner Authentication Baseline

Status: implementation scope; not deployed.
Baseline: v0.40.0 / cd2bc1404cc3e7e607ea3a5cdefb301e8b32f7fe

## Confirmed findings
- External sampled routes require Traefik Basic Auth.
- Local WEB/API data routes accept unauthenticated requests.
- API has no authentication module or global authorization guard.
- Prisma has no owner or session models.
- Global whitelist/forbidNonWhitelisted validation is already enabled.
- WEB shares n8n_network and pnet_backend; API uses pnet_backend.
- Nginx currently forwards its internal scheme as X-Forwarded-Proto.
- Write routes, including message sending, need application authorization.
  No production write requests were made during this audit.

## Owner and bootstrap
- One owner per installation, enforced by a database singleton constraint.
- No public registration, guest mode or public first-owner setup route.
- Dedicated server CLI creates the owner with hidden password input.
- CLI must use Prisma directly and must not start the scheduler.
- TOTP enrollment must be verified before the owner becomes active.
- Repeated/concurrent bootstrap must not create another owner.
- No default credentials or installation-specific identity in Git.
- Provisioning material and recovery codes stay local and out of logs/reports.

## Authentication
- Login plus password plus TOTP; no password-only data access.
- Argon2id password hashes via a maintained library.
- TOTP via a maintained library, with atomic replay prevention.
- Encrypt TOTP secrets with a key stored separately from the database.
- Recovery codes are high-entropy, hashed, single-use and consumed atomically.
- Password plus a recovery code can substitute for the unavailable TOTP factor.
- Generic login errors and bounded, persistent attempt limiting.
- Limit expensive password verification concurrency and auth request sizes.
- TOTP is not phishing-resistant; passkeys are a subsequent enhancement.

## Sessions and API protection
- Opaque random session tokens; only token hashes stored in PostgreSQL.
- Cookies: Secure, HttpOnly, SameSite=Strict, Path=/, no Domain.
- Initial policy: 30-minute idle expiry and 12-hour absolute expiry.
- Enforce expiry and revocation on the server.
- Logout revokes the session; credential recovery revokes all sessions.
- Global Nest guard denies access by default, including future controllers.
- Explicit public exceptions only for login and minimal health.
- Session inspection, logout and all personal-data routes require authentication.
- No localhost, Docker-network or forwarded-identity authentication bypass.
- CSRF token and configured-origin checks for state-changing browser requests,
  including suitable origin/content-type checks on login.
- Do not trust arbitrary forwarded headers.
- Configure the public HTTPS origin and a narrow proxy trust boundary.
- WEB handles expired sessions by returning to login and removing private views.

## Recovery and self-hosting
- Provide a server-only credential/factor reset command with hidden input.
- Recovery must not temporarily open data routes or public registration.
- Document key storage, encrypted backups, recovery codes and session revocation.
- Commit reusable source, migrations, tests and example configuration to GitHub.
- Do not commit actual credentials, encryption keys or provisioning artifacts.
